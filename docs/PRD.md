# SwingLink 产品文档（PRD）

版本：v0.2（讨论稿，明确完整 3D 球场、难度与风系统）
日期：2026-10-26
项目代号：SwingLink
一句话：电脑浏览器显示球场，iPhone 当球杆；两个人隔着太平洋打一场回合制高尔夫。

---

## 1. 背景与问题

### 1.1 起因
两个身处中国和美国的朋友，想一起玩一款接近 Nintendo Switch Sports 高尔夫体验的游戏：
- 大屏在电脑浏览器里，无需安装游戏客户端；
- 手机作为体感球杆，真实挥动；
- 支持跨洋双人联机。

### 1.2 现成方案为什么不满足
| 方案 | 缺口 |
|---|---|
| AirConsole / Golffriends | 面向同一房间，不适合跨洋双人 |
| Golf With Your Friends | 联机成熟，但不支持手机体感挥杆 |
| Switch Sports | 双方都需要 Switch 与会员，跨洋 P2P 体验不稳定 |
| Walkabout / GOLF+ | 体验完整，但双方需要 VR 头显 |
| 虚拟手柄映射 | 只能映射力量条和摇杆，无法让第三方游戏识别真实挥杆，且链路复杂 |

### 1.3 产品判断
这是一个“先单人验证、后续再双人联机”的私人体感小游戏，不是通用游戏平台。当前版本只做本地单人，不部署公网服务。第一目标不是内容量，而是验证：**手机挥杆产生的力量与方向，是否与玩家手上的感觉一致。**

## 2. 目标与成功标准

### 2.1 核心目标
1. iPhone 挥一次，电脑上的球按可理解的力量和方向飞出。
2. 当前版本由一名玩家完成 3 洞快速局或 9 洞完整局；双人跨洋联机仅作为后续扩展。
3. 无需安装手机 App；电脑端只用浏览器；只在本机运行一个轻量本地服务。
4. **大屏必须是完整、统一的 3D 球场**：明亮干净的体育卡通风格，具备球洞节奏、主题环境、风、难度、路线图和果岭坡度；2D 俯视或单纯随机低模地形均不算达标。

### 2.2 非目标（v1 明确不做）
- 不做账号体系、好友列表、公开匹配、排行榜。
- 不做曲球、打厚/打薄、attack angle、杆面角等高级挥杆维度；风是球场规则，不属于额外手势。
- 不做高成本写实 3D；采用明亮、干净、统一的体育卡通 3D，不把 PS1/像素风作为主风格。
- 不做 8 人生存战、公开匹配和复杂赛事；首发专注双人快速局与完整局。
- 不做观众、多人房间管理、聊天系统。
- 不做通用虚拟手柄，不接入第三方商业游戏。
- 不追求物理模拟精度，追求可预期、可调、好玩。

### 2.3 验收标准
| 层级 | 通过条件 |
|---|---|
| 输入可用 | 连续挥 20 次，无误触；每次只产生一次击球 |
| 力量可信 | 轻、中、重三档挥动能稳定产生低、中、高三档距离 |
| 方向可信 | 相同准备姿势下，方向不会整体固定偏向一侧 |
| 推杆可玩 | 果岭上能用轻挥完成短推，不出现“轻轻一碰就飞十米” |
| 联机稳定 | 中美两地连续完成 3 洞快速局；回合不串、球位一致 |
| 球场完整 | 至少有 3 套主题和难度明确的球场；支持 3 洞快速局与 9 洞完整局 |
| 风可读 | 玩家能在击球前看清风向风力，并通过调整方向和力量补偿；同一杆两端结果一致 |
| 异常可恢复 | 一方刷新或断线重连后，能回到当前洞、当前杆数和当前球位 |
| 主观成立 | 两名玩家都愿意再开一局，而不只是“技术Demo看完了” |

## 3. 用户与使用场景

### 3.1 用户
- 玩家 A：中国，Mac/电脑 + iPhone。
- 玩家 B：美国，电脑浏览器 + 手机。
- 双方无固定游戏时间，可能临时开局；需要低准备成本。

### 3.2 主流程
1. 玩家打开电脑上的本地游戏页面，选择球场与赛制：3 洞快速局或 9 洞完整局。
2. 手机扫码进入本机手柄页。
3. 手机完成传感器授权、静止校准、三次试挥校准。
4. 电脑显示“已连接 / 已校准”，播放首洞短飞越，进入第 1 洞。
5. 玩家观察路线图、风向风力、距离与地形，在手机上挥杆；电脑大屏播放球的飞行和滚动。
6. 球停稳后准备下一杆；进洞后显示单洞成绩。
7. 赛制结束显示总比杆与逐洞成绩卡，可一键重赛或换球场。

未来双人模式再增加房间码、邀请链接、双方连接与轮流击球，不影响当前单人流程。

### 3.3 设备与握持约定
- v1 只保证 iPhone Safari；安卓作为后续兼容项。
- v1 统一横握手机，固定挥杆轴；首次实现必须通过实测确认 `rotationRate` 主轴。
- 手机在整个回合中保持页面可见、屏幕常亮。
- 挥杆时确保周围空间安全；产品页面需有简短安全提示。

## 4. 核心玩法

### 4.1 输入维度
v1 只保留两个输入：

| 输入 | 玩家动作 | 游戏含义 |
|---|---|---|
| 力量 power，0–1 | 下挥角速度峰值 | 决定初速度和距离 |
| 方向 dir，-1–1 | 准备/挥杆时手机左右倾斜相对基准的偏移 | 决定出球左右方向 |

为什么不做更多：
- 手机传感器采样密度足够取峰值，不足以可靠还原完整杆头轨迹。
- 打厚/打薄若无法稳定测量，只会表现为随机惩罚。
- 选杆、弹道高低属于游戏规则，不应增加手势负担。

### 4.2 力量手感
- 力量采用非线性曲线，初始使用 `power = normalizedPeak ^ 1.6`。
- 目的：拉开轻挥区间，让切球和推杆有细腻度。
- 不允许写死“所有人的满力角速度”；每位玩家独立校准满力基准。
- 支持随时重新校准；校准数据保存在各自手机本地。

### 4.3 方向手感
- 静止时记录方向零点，消除握持差异。
- 方向偏移先限幅，再映射到最大出球偏角。
- v1 不做“手腕翻转产生左右曲球”；该能力列入 v2 候选。

### 4.4 果岭模式
- 是否进入果岭由游戏侧根据球位判断，手柄不需要知道。
- 进入果岭后：力量上限压缩到约 15%，方向影响缩到约 30%。
- 玩家仍使用相同挥杆动作，不要求换一套操作方式。
- 球速过快可跳洞，只有低速进入洞杯范围才判进洞。

### 4.5 球场、难度与风（核心体验）

**首发内容目标：3 套完整 9 洞球场；同时提供 3 洞快速局和 9 洞完整局。** 技术验证仍从 1 洞开始，不把“首发 3 洞”误当成最终内容量。

| 球场 | 难度与个性 | 主要设计手段 | 风的角色 |
|---|---|---|---|
| 晴空公园 | 入门 | 宽球道、少水、平缓果岭、清楚落点 | 弱风为主，帮助理解顺风/逆风 |
| 海岸林克斯 | 进阶 | 狭窄落球区、沙坑、水障碍、更明显果岭坡度 | 持续侧风，要求主动瞄准补偿 |
| 山谷松林 | 困难 | 狗腿、树道、高差、小果岭、风险捷径 | 风向变化更多，但单杆飞行中绝不改变 |

球场难度不能只靠“风更大”，要同时由球道宽度、落点、障碍、高差、果岭面积与坡度构成。同一球洞可有多个旗位，形成重赛变化。

每洞体验必须包含：
- 发球前的短飞越或球洞总览；
- 路线图、剩余距离、Par、当前杆数；
- 自动球杆/击球模式提示（开球、攻果岭、切球、推杆），v1 不要求玩家用手势选杆；
- 明确风向箭头与风力数值，并能看出相对击球方向的顺风、逆风、侧风分量；
- 果岭坡度可读，推杆前能查看高低差。

风规则：
- 每洞由房间种子生成风向和风力，服务器下发，双方一致；
- 一杆挥出后风保持恒定，不在球飞行中随机变化，不用阵风制造不可解释结果；
- 风主要影响飞行段，推杆不受影响；
- 难度提高时扩大风力与侧风出现概率，但必须设上限，保证补偿可学习。

基础规则：
- 发球台、球道、长草、果岭、沙坑、水障碍、界外；
- 沙坑降低滚动并限制下一杆力量；水障碍/界外加 1 杆，回到上一击球点或指定落球点；
- 固定 2 人比杆，当前玩家球完全停稳后换手；同杆并列；
- 支持重赛与换场，不保存长期生涯数据。

### 4.6 球场生产与美术方向
- 球洞以“中心线 + 地形高度场 + 地表类型 + 障碍 + 装饰种子”描述，不手工制作大量独立模型。
- 3D 地形由程序生成；树木、草丛、岩石使用低模 GLB 资源，通过旋转、缩放和随机分布形成变化。
- 首版美术目标是明亮、干净、色彩统一的体育卡通 3D；素材包只是零件，必须统一模型尺度、色板、光照、天空、水面、镜头和音效，不能呈现“随机地形上插树”的拼装感。
- 每套球场有独立的色彩与环境身份，但共用 UI、球、旗杆和交互语言。
- 内容优先级：先完成一套有统一美术与节奏的球场，再扩展另外两套；程序生成负责提高产量，人工负责球洞 routing、难度与最终验收。
- 后续可接 OpenStreetMap 的球道/果岭/沙坑几何，作为 3D 球场的平面布局，再由程序补地形和装饰。
- 所有第三方资源必须记录来源和许可证；优先 CC0，代码参考与素材引用分开记录。

## 5. 页面与交互

### 5.1 电脑大屏页
必须包含：
- 房间码与连接状态；
- 两名玩家昵称、当前回合、当前洞、各自杆数；
- 球、洞杯、完整 3D 地形、球洞路线图与击球方向预览；
- 风向/风力、剩余距离、自动球杆或击球模式、果岭高差提示；
- 当前玩家“请挥杆”提示与试挥反馈；
- 开球前球洞飞越、球飞行/滚动和跟球镜头；
- 校准未完成、手机断连、等待对手等明确状态；
- 每洞成绩与总成绩卡。

不需要：
- 复杂菜单、商城、设置中心；
- 写实人物、球杆模型；
- 高频实时同步球位。

### 5.2 手机手柄页
按顺序提供：
1. 安全提示与“开始连接”按钮（用户点击同时触发传感器授权）。
2. 传感器权限状态、连接状态。
3. 静止校准提示。
4. 三次试挥校准，显示每次峰值与完成情况。
5. 正式挥杆页：大号“准备”状态、最近一次力量/方向、是否已发送。
6. 重新校准入口。
7. 防锁屏失败或传感器中断时的明确提示。

调参模式（开发版）：
- 显示原始角速度峰值、归一化力量、方向值、状态机当前状态。
- 支持导出最近 50 次挥杆日志。
- 正式游玩时可隐藏，但能力必须保留。

### 5.3 反馈
- 手机：击球时用短振动/视觉闪烁确认（设备支持时）。
- 大屏：击球瞬间播放简单音效；球飞行和落地有明确视觉反馈。
- 反馈必须在本地立即触发，不能等待跨洋服务器往返后才让玩家知道“挥杆被识别了”。

## 6. 联机体验规则

- 房间以房间码加入，不注册账号。
- 服务器负责回合和最终球位；两端只播放结果动画。
- 当前玩家挥杆后，本地立即显示“已识别”，远端等待服务器确认。
- 球运动中锁定新的击球输入，避免重复挥杆改变状态。
- 掉线不直接判负：保留房间至少 10 分钟，允许凭原房间码和昵称重连。
- 对手掉线时显示等待状态，可由房主选择结束本局。
- 跨洋延迟只影响“看到对手结果的时间”，不应影响本地挥杆识别手感。

## 7. 里程碑

| 阶段 | 交付 | 验证重点 |
|---|---|---|
| M0 输入试纸 | 无球场，只显示力量、方向、峰值与日志 | 唯一高风险项：手感是否成立 |
| M1 单洞单机 | 1 个完整 3D Par 3，从发球到进洞 | 力量曲线、果岭模式、跟球镜头、进洞判定 |
| M2 首球场三洞 | 晴空公园前 3 洞、统一美术、风与路线图 | 球场是否完整、风是否可读、处罚规则 |
| M3 跨洋双人 | 公网房间、3 洞快速局、回合、重连、成绩卡 | 球位与风一致、断线恢复 |
| M4 完整内容 | 首套 9 洞，再扩展海岸与山谷两套 9 洞 | 难度差异、重玩价值、性能 |

原则：M0 未通过，不进入球场和联机开发。

## 8. 风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| 手感不成立 | 数字和动作对不上，轻挥也满力 | 先做 M0；保留日志；只调参数不改架构 |
| iOS 证书/权限卡住 | 页面打开但无传感器数据 | 把证书信任、HTTPS、点击授权写成固定检查清单 |
| 手机采样不足 | 曲球/轨迹判定抖动 | v1 只做力量与方向，不做轨迹识别 |
| 锁屏或切后台 | 挥杆中数据停止 | 页面常亮、wakeLock、中断提示 |
| 两端球位不同 | 看到不同结果 | 服务器唯一计算，端侧不各自裁定 |
| 3D 好看但跑不动 | 树木/阴影导致卡顿、发热 | 低模、实例化植被、限制阴影与像素比，先保证跟球流畅 |
| 玩法很快腻 | 打完一次不再打开 | M4 再投资内容；优先调手感和球场，而非加输入维度 |

## 9. 待确认决策

以下已有默认值，不阻塞 M0；进入 M1 前确认即可：
1. **球场内容**：已确定首发目标为晴空公园、海岸林克斯、山谷松林三套 9 洞；支持 3 洞快速局与 9 洞完整局。
2. **视觉表现**：已确定为明亮干净的体育卡通 3D；PS1/像素只可作为后续特殊滤镜，不作为主风格。
3. **玩家人数**：v1 锁 2 人；协议可预留 4 人，但不实现多人规则。
4. **手机姿势**：默认统一横握；若实测主轴不稳定，再改握持方式。
5. **后续候选**：曲球/下旋、18 洞组合、更多旗位、轻障碍、表情/语音。优先级由实际双人游玩反馈决定。
