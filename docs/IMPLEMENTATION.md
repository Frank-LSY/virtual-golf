# 实现与验证记录

## 已实现的本地功能

- 晴空公园、海岸林克斯、山谷松林，每套 9 洞；支持 3 洞和 9 洞。
- 连续三维高度场地形、球道、长草、果岭、沙坑、水、树木、岩石、旗杆、球与镜头动画。
- 服务端与渲染使用相同球场数据；每洞风况在击球前确定。
- 固定步长的飞行、弹跳、滚动、坡度、树干碰撞、低速进洞、落水/出界处罚与 12 杆上限。
- 自动选杆、瞄准、键盘蓄力、路线图、相对风向、距离、果岭网格和成绩卡。
- 本地 HTTP/HTTPS、二维码配对、消息校验、序号去重、输入锁定、心跳、重连与存档。
- iPhone 权限、分步握姿归零、自动找轴、轻/舒适挥幅采样、两次复测、校准复用、状态机、冷却、常亮与中断提示。
- 挥杆练习室、调参、最近 50 条记录、手感标记、漏识别标记、中文 JSON/CSV 导出。

## 0.6.0 多人及引导校准

支持明确选择 2–16 人并勾选对应手机。服务端按稳定手机身份校验控制权；每杆轮换、独立球位/瞄准/杆数/罚杆/成绩，全部完成后再推进球洞。断线取消准备但保留球手，不自动切换到其他手机。多手机配色与姓名在 3D 画面及记分卡中显示；人数较多时名单可横向滚动。

训练状态按手机隔离并持久化，切换手机清除未应用草稿。校准采用明确的一次动作采样、三轴能量判断、轻挥/舒适挥幅分离、两次 50% 目标带复测。错误动作、混合轴、相近力度、握姿偏转、断流、切后台均有具体反馈。确认后才使用新结果；支持仅重置握姿。

35 组自动测试通过，包含实际手机控制器的完整校准流程、同伴校准消息不打断当前动作、2/3/4/6/8/16 人轮次、独立记录、控制权及断线恢复。HTTP/HTTPS/单手机集成测试通过。独立多手机 WebSocket 集成测试涵盖双手机完整击球、独立调参和校准请求、记录落盘与归档、重复身份替换，以及 3/4/6/16 人建局和人数不符拒绝。

浏览器使用两个不同本机地址的独立手机页面，检查身份/昵称、名单选择、第三人称双球手、当前控制提示、练习室选择手机与定向校准请求。没有真实运动传感器，完整动作由模拟事件验证。手机实机、16 台实体设备同时连接和 Mac 真机性能仍待验证。校准设计参考 https://www.nintendo.com/jp/ichikara/as8sa/index_en.html ，没有真实手感优于 Nintendo Switch Sports 的对照结论。

Mac 0.6.0 Apple 芯片和 Intel 包按当前源文件生成，使用既有打包器进行完整性、架构、脚本执行权限、源文件一致性和私钥隔离校验。

## 0.8.0 树木碰撞与落水反馈（2026-10-27）

根因：旧树木已有三维网格，但物理模型只检测树中心 0.8 × 缩放的窄柱，既没有树冠范围，也没有检查一帧内跨越的完整路径。现在 shared/trees.js 为可见网格与服务端碰撞共用顶点、面和实例变换。阔叶树包含三组圆润树冠，松树包含三层锥形树冠；树干为截锥。球半径扩展凸面后进行连续段扫掠，选最早接触点，并按法线分离法向反弹与切向减速。树冠比树干更柔软，不再统一翻转水平速度或退回整帧起点。树冠仍是简化凸体，不是逐片树叶模拟。

碰撞反馈包含树干木屑、树冠碎叶、局部枝叶晃动与不同音效；特效根据服务端事件时间播放一次，正式场景与练习室共用。接触点加入实际轨迹，彩虹拖尾也随反弹转向。每杆碰撞记录保存在当前球手名下，中文导出包含碰撞种类、位置、时间及碰撞前后速度。

水域在实际水面 0.1 米处检测，而不是等球接触水底。高空飞越不触发，水面以上的干岸可继续打球，水覆盖沙坑时优先按水判定。落水保留 1.25 秒独立播放时间：喷溅水滴、扩散涟漪、下沉与拖尾淡出；水面增加动态波纹。近景从水域中心一侧观察，并在落水瞬间切换，避免镜头穿入停放球车。沿用游戏既有落水加罚一杆并返回原球位的规则；界外海面仍按出界规则处理。服务端的回合等待包含落水展示，不能在动画中抢先击球或轮换。

验证结果：

- 53 项自动检查通过。新增检查覆盖共用网格与凸面、树干高速穿越、阔叶/松树树冠、空隙和越顶球、地面和空中真实击球反弹、确定性、实际水面、高空越水、干岸、水面侧镜头、下沉采样、拖尾停止、粒子去重与清理、罚杆和球手归属。
- HTTP / HTTPS 连接回归、独立训练、重复输入拒绝、重连和保存通过；多人回归覆盖两部手机独立身份/校准/调参/记录及 3 / 4 / 6 / 16 人建局。
- 浏览器通过正常选杆、瞄准、力量、准备和击球按钮验证：树干接触与反弹提示、落水水花和涟漪、无遮挡近景、每次增加两杆（本次击球一杆和落水罚一杆）、返回原球位后操作恢复。页面无运行错误。使用 .local/tree-preview 与 .local/water-preview 隔离存档，未修改用户默认球局。实际水花截图：.local/water-impact-0.8.0.png。

- 洞口：`cupContact` 外缘 = 洞半径 + 0.55 球半径；留球上限 `captureLimit(q) = 2.35 × (1 − 0.42·min(q,1.2)²)`（原 1.9 × (1 − 0.55q²)），偏心 q < 1.12 可绕洞落杯（原 q < 1）；q > 1.2 或 > 3 米/秒为擦边。`cupFunnel`：0.6 米内、2.6 米/秒以下的滚球受至多 0.32 米/秒² 的向心加速度。
- 旗杆（`PIN_RADIUS` 0.035、`PIN_HEIGHT` 3.1，与画面一致）：滚动中偏心 < 旗杆半径 + 球半径且快于留球上限时，3.6 米/秒以内记为 `pin_drop`（进洞），更快为 `pin_bounce`（沿法线弹回）；空中用 `sweepPin`（竖直圆柱求交）检测，`pinBounce` 法向弹回 0.28、切向保留 0.5、竖直 0.75。落地点在洞口内（距洞心 < 洞半径 − 0.2 球半径）且入射 < 26 米/秒记为 `dunk`（直接落杯）。`options.flagstick:false` 可模拟拔旗杆；预判与练习场（`capture:false` / `practice`）不考虑旗杆。
- 树冠改为软体：球与叶团接触时速度乘 0.5 并略向外、向下偏转（`leafEntry`），之后在该树冠内每秒阻尼 2.6（`LEAF_DRAG`），用 `insideCrown`（含 5 厘米余量）判断穿出；穿行中的树冠不再阻挡。树干顶面（藏在树冠里）不作平台：球被拨向外侧落下。修复：0.21 及以前，球落在树冠顶部会因每步微弱反弹而停在树上直到 35 秒模拟上限（抽样中 168 杆里出现）。
- 岩石：`makeRocks` 在服务端生成（与原画面相同的随机序列种子），只放在长草区，离球道中心线 > 宽度 + 5 米、离旗杆 > 果岭半径 + 7 米、离发球台 > 16 米，并与树干、其他岩石保持距离；碰撞体为 Three.js 十二面体（半径 1.6）经缩放与 XYZ 欧拉旋转后的凸包（`rockVertices`、法线 R·S⁻¹·n），恢复系数 0.42、切向 0.74，碰撞事件类型 `rock`。
- 预判：`Game.forecast` 每档力度另算当前风下的 `windLanding` / `windEnd`（推杆不算）。

球局流程（`local-gateway/round-channel.js`、`game-service/game.js`）：
