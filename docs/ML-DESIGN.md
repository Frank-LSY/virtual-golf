# 挥杆之间 · 机器学习挥杆识别设计

版本：v0.1（与游戏 0.15.0 同步）
目标：用手机 6 轴传感器的短时序列学会“这是什么动作、用了多大力”，并随每一次挥杆持续变准；换人、换手机时只需约 2 分钟的少量样本就能达到可用精度。

---

## 1. 为什么要从阈值规则换成学习

现有识别是“主轴角速度过阈值 → 符号翻转 → 峰值衰减”的状态机，力量 = 峰值 / 满力校准值。问题：

- 只看一根轴的峰值，换握姿、换手机、换人后主轴和量级都会变，需要重新手调阈值。
- 拿起放下、甩手腕这类动作只要峰值够大就会误触发；推杆这种低速动作又容易漏识别。
- 峰值只是一个点，无法利用上杆节奏、下挥时长、收杆等完整形态。

学习方法用整段序列做判断，并把“个人差异”留给可在线更新的小部分参数。

## 2. 任务定义

### 2.1 输入

| 项 | 规格 |
|---|---|
| 原始通道 | 角速度 `rotationRate` α/β/γ（°/s）+ 含重力加速度 `accelerationIncludingGravity` x/y/z（m/s²），共 6 轴 |
| 设备采样 | iPhone Safari 约 60 Hz，部分设备 100 Hz；逐点保留原始时间戳 |
| 统一采样 | 按时间戳线性插值到 **50 Hz** 等间隔，消除设备采样率差异 |
| 对齐方式 | 以平滑后 \|ω\| 的最大值为锚点，取 **[峰值前 1.80 s, 峰值后 0.12 s]**，共 96 帧（1.92 s） |
| 朝向归一 | **挥杆坐标系**：z′ = 起杆前静止时的重力“上”方向；x′ = 该窗口角速度的主旋转轴（投影到水平面，符号由峰值时刻的 ω 决定）；y′ = z′ × x′。ω 和 a 都旋转到这个坐标系后再送入模型 |
| 模型通道 | 8 通道：ω′x、ω′y、ω′z、\|ω\|（÷400）；a′x、a′y、a′z、\|a\|（÷9.81） |

挥杆坐标系让同一个动作无论手机竖握、横握、屏幕朝里朝外，还是换了一台坐标轴定义不同的手机，输入都几乎相同（测试中任意旋转后窗口差异 < 2%）。这是“换设备简单微调即可用”的主要来源；剩下的差异（握姿偏斜、力量、节奏）交给数据增强和个人适配。

窗口是**因果**的：峰值后 120 ms 即可做出判断，满足“本地反馈 < 0.2 s”的手感要求；收杆阶段只在采集时保存，不进入实时判断。

### 2.2 输出（多任务）

1. **动作类别**（4 类，softmax）：`full` 全挥杆、`partial` 切杆 / 半挥杆、`putt` 推杆、`other` 非挥杆动作（拿起放下、晃动、走动、预备晃杆）。
2. **力度分数** `s`（标量）：只要求“同一个人、同一类动作里，用力越大分数越高”，不要求绝对数值。
3. **嵌入向量** `e`（32 维）：用于个人原型分类与新设备快速适应。

游戏中的最终力量 `power ∈ [0,1]` 由每位球手、每类动作各自的**力度映射**把 `s` 转换而来（§5）。

### 2.3 为什么分这四类

- `full / partial / putt` 对应游戏里不同的力量刻度和推荐球杆，节奏与幅度差异明显。
- `other` 是“开放集”的拒识类，是压低误触发的关键；推理时再加置信度阈值，低于阈值一律视为非挥杆。

## 3. 模型：SwingNet（小型 1D 卷积 + 度量学习头）

```
输入 8×96
 └ Conv1d 8→16, k7 → ReLU → MaxPool2      (16×48)
 └ Conv1d 16→24, k5 → ReLU → MaxPool2     (24×24)
 └ Conv1d 24→32, k3 → ReLU                (32×24)
 └ 全局平均池化 ⊕ 全局最大池化 → 64 维“编码特征” h
 └ Dense 64→32 → 嵌入 e
     ├ Dense 32→4 → 类别 logits
     └ Dense 32→1 ⊕ 幅度旁路 [log(1+4·峰值), log(1+4·均方根)] → 力度分数 s
```

- 约 **7.4 千参数**，权重 JSON 约 40 KB；手机上一次推理不到 1 ms，纯 JavaScript 实现，无需额外库。
- **选型理由**：IMU 动作识别中，小型 1D-CNN + 全局池化在小数据上稳定、对时间偏移不敏感；比 LSTM/GRU 训练快、易在 JS 中实现反向传播；比 Transformer 更不容易在几百个样本上过拟合。手工特征 + 树模型虽然在小数据上很强，但难以逐杆增量更新，也没有可用于原型适配的嵌入空间，因此只作为评估时的参照基线。
- **分层冻结**：卷积编码器（约 5.2 千参数）只在“完整训练”时更新；嵌入层与两个输出头（约 2.2 千参数）可以在线微调。编码特征 `h` 会被缓存，在线微调只需在 64 维特征上做几轮小型全连接训练，耗时远低于一秒。

### 3.1 损失

- 类别：带类别平衡的交叉熵。
- 力度：**成对排序损失**（RankNet）。只在同一球手、同一类挥杆、提示档位不同（轻 < 中 < 重）的样本对之间计算：`log(1 + exp(-(s_hi - s_lo)))`。不需要绝对力度标签。
- 权重衰减 1e-4；Adam，学习率 3e-3，批大小 32，约 40 轮。

### 3.2 数据增强（为跨人、跨设备迁移服务）

| 增强 | 模拟的差异 |
|---|---|
| 随机三维旋转（同时作用于 ω 和 a，±30°；10% 概率交换 / 翻转轴） | 握姿不同、横握方向相反、不同机型坐标系 |
| 角速度幅度缩放 0.7–1.4；参与排序损失的样本只缩放 0.93–1.07 | 力量大小不同的人（又不破坏同一人轻 / 中 / 重的先后） |
| 时间伸缩 0.8–1.25 | 挥杆节奏快慢 |
| 锚点平移 ±3 帧、高斯噪声 | 峰值定位误差、传感器噪声 |
| 降采样到 45–100 Hz 再插值回 50 Hz | 设备采样率不同 |

## 4. 数据采集

### 4.1 引导式采集（练习室“数据采集”页 + 手机采集模式）

1. 电脑选择手机和“采集对象”（球手姓名，同一手机可代表不同的人），再选动作类别、力度档位和次数。
2. 手机显示大号提示（例如“全挥杆 · 中等力度 · 第 3/10 次”）。手机静止 0.5 秒后提示“请挥杆”；角速度超过起始阈值自动开始录制（含 1 秒预录），静止 0.45 秒或满 4 秒自动结束。
3. 录制太短、太弱会提示重来；成功则闪绿并上传，电脑实时显示波形、锚点和对齐窗口。
4. “非挥杆动作”会依次提示：拿起手机、放下手机、随手晃动、走几步、预备晃杆（不挥出）、转身看屏幕。
5. 力度档位可选“轮换”，自动按 轻 → 中 → 重 循环，保证排序损失有足够的对比对。

建议的最小数据量（每位球手、每台手机）：全挥杆 30、切杆 20、推杆 20、非挥杆 30，每类挥杆三档力度各约三分之一。约 15 分钟可以采完。

### 4.2 实战挥杆（每一杆都入库）

- 正式球局和练习室里，规则识别每触发一次挥杆，手机就把触发前 2.6 秒的 6 轴数据作为 `play` 样本上传，附带当时的球杆、模式、规则力量与方向。
- 手机上的“误触发”标记会把对应样本改标为 `other`；“漏识别”会上传最近 5 秒作为待复核样本。
- 弱标签来自球杆：推杆 → `putt`，劈起杆 → `partial`，一号木杆 / 铁杆 → `full`，挖起杆与沙坑杆不给弱标签。

### 4.3 数据格式

- 传输与存储都使用 Int16 Base64：时间戳 1 ms、角速度 0.1 °/s、加速度 0.005 m/s² 精度。5 秒 60 Hz 录音约 5.6 KB，低于 WebSocket 16 KB 上限。
- 存储位置：`.local/ml/index.json`（可修改的元数据：标签、档位、来源、预测、删除标记）+ `.local/ml/raw-YYYYMM.jsonl`（只追加的原始数据）。只留在本机，可在练习室导出。

## 5. 力度：弱监督 + 无标签自适应

每位球手（人 × 设备）、每类挥杆各维护一个**力度映射**：

1. **分布估计（无标签）**：保留最近 300 个被接受挥杆的分数 `s`，取 2% 与 97% 分位数作为个人力度区间的下限和上限，随每次挥杆自动更新。
2. **档位锚点（弱标签）**：采集时“轻 / 中 / 重”三档的分数中位数分别锚定到 25% / 55% / 90%。
3. **映射**：把 (下限 → 5%)、(轻 → 25%)、(中 → 55%)、(重 → 90%)、(上限 → 100%) 连成单调分段线性函数；没有锚点时只用分位数区间线性映射，再沿用原有的力量曲线指数。

这样不需要知道“真实挥杆速度”，也能学出“这个人的轻、中、重分别是多少”，并随实战逐渐校正。

## 6. 持续学习：每一杆都让模型更准

| 层级 | 触发 | 更新内容 | 防止遗忘 |
|---|---|---|---|
| 即时 | 每个被接受的挥杆 | 个人类别原型（嵌入均值，指数平均 α=0.1）、力度分布 | 只改该球手的少量统计量 |
| 周期 | 每新增 15 个被接受的实战样本；快速适应结束时立即一次 | 冻结编码器，在缓存的编码特征上微调嵌入层和输出头 5 轮，完成后自动部署并按新模型重建所有个人原型与力度映射 | 训练集 = 全部人工标注样本 + 已接受的伪标签（按权重、类别平衡），而不是只用最近几杆 |
| 完整 | 练习室手动“完整训练”，或标注数据增长 30% 后提示 | 全网络重新训练 | 使用全部标注数据和高置信伪标签 |

**样本是否被接受**（伪标签策略）：

- 人工标注（采集、复核改标、误触发标记）→ 强标签，权重 1。
- 实战样本：模型置信度 ≥ 0.85 且与球杆弱标签一致 → 伪标签，权重 0.5。
- 没有球杆弱标签（挖起杆、沙坑杆）时，只有置信度 ≥ 0.95 的挥杆类预测才接受，权重 0.3；模型判为 `other` 的实战样本永不自动接受。
- 不一致或置信度不足 → 进入“待复核”，不参与训练，直到在练习室确认。

## 7. 换人、换设备的快速适应

1. 输入先旋转到挥杆坐标系（§2.1），编码器在训练时又见过旋转、缩放、节奏和采样率扰动，对握姿和设备差异有较强的不变性。
2. 新的“人 × 设备”在练习室运行**快速适应**（约 2 分钟）：全挥杆 5、切杆 5、推杆 5（轻中重轮换）、非挥杆动作 6 次。
3. 用这些样本计算个人类别原型和力度锚点，并在冻结的编码特征上微调输出头。
4. 预测时把全局输出头与个人原型距离融合：`p = softmax(w·z_global + (1−w)·(−‖e−c_k‖²/τ))`，个人样本越多，原型权重越大（`w` 从 0.7 逐步降到 0.4）。
5. 评估：留一人（或留一设备）交叉验证，报告“零样本”和“5 样本适应后”的宏平均 F1，量化迁移效果。

## 8. 部署与上线顺序

1. **采集阶段**（本版本）：规则识别照常工作，同时收集采集样本和实战样本。
2. **影子模式**：模型训练完成并部署后，在手机与服务器上与规则并行推理，只记录、不影响击球；练习室显示一致率、模型会拒识的误触发、模型能补上的漏识别。
3. **切换**（0.16.0 已实现）：练习室“模型训练”页与手机上都有“改用模型识别”开关，默认开启；当前部署的模型含流式训练时手机改用模型识别，否则自动退回规则。练习室列出建议门槛（验证 F1 ≥ 85%、流式准时识别 ≥ 85%、非挥杆误触发 ≤ 10%），未达标也允许开启。详见 §12。

## 9. 评估指标

- 宏平均 F1、混淆矩阵（按采集批次划分训练 / 验证集，避免同一批相邻样本泄漏）。
- 误触发率：`other` 被判为任一挥杆类的比例。
- 漏识别率：挥杆被判为 `other` 的比例。
- 力度：同一球手同类挥杆中 `s` 与档位的 Spearman 相关；三档两两排序正确率。
- 迁移：留一人 / 留一设备的零样本与 5 样本适应 F1。
- 参照：规则识别器在同一数据上的触发率，以及手工特征最近质心基线。

## 12. 流式模型识别（0.16.0）

### 12.1 从“分类一段录音”到“在数据流里找挥杆”

采集样本是已经切好的录音，锚点取整段的 |ω| 最大值；实战中手机面对的是连续数据流，必须在击球后很短时间内决定“这是不是一次挥杆”。做法：

1. **候选峰值**：|ω| 做 3 点因果平均；出现局部最高点且之后 130 ms 内没有更高值，就形成一次候选（峰值 ≥ 50 °/s）。判断过的峰值在角速度回落到 45% 以下后清除，之后必须从谷底重新明显上升才形成新候选，下坡上的抖动不会触发。
2. **判断**：取候选前 2 秒的数据，重采样后在候选附近找锚点，截取与训练相同的 8×96 窗口，SwingNet 推理（Node 中中位数约 0.9 毫秒）。
3. **触发**：全局输出头判为挥杆类、且置信度 ≥ 触发阈值（默认 70%）即发送挥杆。随后冷却 1.5 秒，并等手机静止 150 ms 后才判断下一次，收杆与回到站位的动作不会再触发。

同一个上杆—下挥动作通常产生两个候选：上杆峰（约在下挥峰前 0.3–0.5 秒）和下挥峰。模型必须拒绝上杆峰，否则会提前击球。

### 12.2 困难负样本

训练时用**同一套候选逻辑**回放每条录音：

- 挥杆录音中，下挥峰之前的候选（上杆峰、预备晃杆）作为“非挥杆”负样本；下挥峰之后冷却期内的候选不用（实际运行时已被冷却屏蔽），冷却期之后的候选也作为负样本。
- 非挥杆录音中的所有候选都作为负样本。
- 负样本权重 0.6，每条录音最多 6 个；只用于训练，不计入分类指标；划分验证集时跟随原始录音，避免泄漏。

在真实数据上对比（同一份数据、5 折交叉验证、阈值 70%）：不加困难负样本时，70 次挥杆中 13 次在上杆峰就提前触发，非挥杆误触发 4/20；加入后提前触发降为 0–1 次，准时识别从 48/70 提高到 64–67/70。

### 12.3 为什么触发只看全局输出头

个人原型融合能帮助区分已标注过的动作，但上杆峰窗口从未作为原型样本出现，融合后它常被拉向“推杆 / 切杆”原型。真实数据 5 折回放：不加困难负样本时，全局头提前触发 13 次、融合 28 次；加入困难负样本后两者的提前触发都接近 0，但融合的非挥杆误触发为 6/20，全局头为 0/20。因此流式触发只用全局输出头（它见过困难负样本）；个人原型继续用于数据集复核、伪标签和电脑端的预测显示。

### 12.4 力量、方向与节奏（免校准）

- **力量**：依次使用这个人在这台手机上的力度映射 → 所有球手合并的“总体映射”（新球手、新设备立刻可用）→ 按角速度峰值估算（全挥杆 1000、切杆 900、推杆 500 °/s 为满力）。手机上的“力量灵敏度”仍作为倍率生效。
- **方向**：沿用原来的定义（起杆时手机的倾角），但零点不再需要“握姿归零”：按全挥杆 / 切杆 / 推杆分别取这个人最近 30 杆起杆倾角的圆周平均，作为习惯零点；偏离习惯越多，出球越偏。每类的第一杆方向为 0。
- **节奏**：从窗口中找上杆顶点（下挥前的低谷）和上杆起点，得到上杆 / 下挥时长，供练习室显示节奏比。

### 12.5 让每一杆都留下训练数据

- 模型触发的每一杆：1 秒后上传 [峰值前 2.6 秒, 峰值后 1 秒]，附带模型判断、力量来源、规则是否也会触发，进入伪标签与在线微调流程。
- **待定动作**（新来源 `candidate`，进入待复核）：规则触发而模型没有触发的动作，以及模型差一点触发（某个挥杆类概率 ≥ 30%）的动作。前者帮助发现漏识别，后者帮助发现边界样本。
- 每条录音都记录采集对象、动作与力度、设备名称（手机上可填写，默认从浏览器标识解析为“iPhone · iOS 18.7”这样的名字）、识别方式。
- 手机上的“录入训练数据”可以不经过电脑直接开始一组采集或快速适应。

### 12.6 真实数据结果（一位球手、一台 iPhone，90 条引导采集）

| 评估方式 | 准时识别 | 提前触发 | 非挥杆误触发 |
|---|---|---|---|
| 阈值规则（回放同一数据） | 54/70（77%）；推杆仅 9/20 | 3/70 | 10/20（50%） |
| SwingNet，5 折交叉验证 × 3 个随机种子 | 64–67/70（91–96%） | 0 | 1–3/20（5–15%） |
| SwingNet，练习室完整训练的验证集 | 约 89–94%（18 次挥杆） | 0 | 0/4 |
| 所有录音串成一条连续数据流回放（训练内） | 69/70 | 0 | 0 次多余触发 |

局限：如果整组验证样本来自**没有参与训练的采集批次**（留一批次），F1 只有约 0.58。这位球手两组推杆的峰值分别为 260–930 °/s 和 70–290 °/s，两组切杆也比全挥杆更快，说明批次之间动作风格差别很大。对策是每类动作分几次、在不同状态下采集，并在实战中让模型持续学习（伪标签、待定动作复核、每 15 杆微调）。

## 13. 手腕转动、竖握与姿态解算（0.17.0）

### 13.1 问题

用户挥杆时常不自主地转动前臂和手腕。在你的真实数据里，全挥杆从起杆到击球手腕平均转动约 −11° 到 −28°（每杆波动约 ±10°），快速推杆约 −30°，慢推杆接近 0。

0.16 的“挥杆坐标系”对整个窗口只用一个固定旋转。它能消除握法这类固定差异，但手腕在挥杆中途转动时，挥杆主轴在手机坐标里随时间变化，信号会从一个通道漏到其他通道。

把真实录音在测试时人为加上 ±60° 的手腕转动后，0.16 模型的准时识别从 64–67/70 掉到 49–51/70。

### 13.2 修正算法：姿态解算后的参考系（特征版本 2）

1. **轴序校验**：iPhone Safari 的 `rotationRate.alpha / beta / gamma` 依次对应设备 x / y / z 轴，与加速度计同序。依据：用真实录音积分陀螺仪去预测重力方向，这种轴序与加速度计平均相差 4.8°，其余 47 种轴序与符号组合都更差。
2. **姿态积分**：在窗口内从第一帧开始积分（中点角速度 + 四元数精确指数映射），把每一帧的角速度和加速度都转到“窗口起点”的固定参考系。窗口只有 1.92 秒，陀螺仪零偏 3 °/s 时漂移小于 6°，因此不做重力校正。
3. **参考系里的挥杆坐标系**：z′ 为重力上方，x′ 为角速度主轴的水平投影，y′ = z′ × x′。
   - 参考系固定在世界中，挥杆平面法线不会因为手腕转动或握法而改变。
   - 加速度在参考系里是“世界加速度 + 重力”，与握法完全无关。
   - 手腕转动只表现为平面内的一小部分角速度，再由数据增强教模型忽略。
4. **兼容**：模型记录 `features`。0.15–0.16 训练的模型（特征版本 1）继续按原方法推理；完整训练会生成版本 2 的模型并自动替换旧版。

### 13.3 数据增强

- **任意握法**：一半样本做均匀随机三维旋转，覆盖竖握、横握、屏幕朝里朝外；另一半仍做 ±30° 小旋转。
- **手腕转动**：手机相对手掌绕“杆身”方向转动 φ(t)。杆身方向取挥杆平面内、与主旋转轴垂直的方向，25% 的概率取随机轴。
  - φ(t) 包括：在下挥峰附近的一次平滑转动（±60°，时长 0.2–0.6 秒），加上 0.5–2.5 Hz、最大 12° 的缓慢抖动。
  - 按物理关系同时改写陀螺仪与加速度计：ω′ = Rφᵀω + φ̇s，a′ = Rφᵀa。
  - 参与力度排序的样本只用 ±30°，以免扭曲同一人的轻中重比较。
- **陀螺仪零偏**：每轴 ±3 °/s，模拟传感器漂移对姿态积分的影响。

### 13.4 真实数据对比（5 折交叉验证 × 2 个种子，触发阈值 70%）

| 配置 | 原始录音 准时识别 | 加 ±60° 手腕转动后 准时识别 | 加转动后 F1 | 任意握法旋转后 |
|---|---|---|---|---|
| 0.16（固定旋转，原增强） | 64–67/70 | 49–51/70 | 0.79 | 不变 |
| 固定旋转 + 新增强 | 65–66/70 | 53–59/70 | 0.85–0.88 | 不变 |
| **0.17（姿态解算 + 新增强）** | 66–68/70 | **59–63/70** | **0.88–0.92** | 不变 |

两项修正各有贡献，合在一起效果最好。原始录音上的非挥杆误触发为 2–3/20，与 0.16 处在同一波动范围内。

### 13.5 握法建议

推荐**竖握**：双手上下叠握手机下半部，像握球杆一样，手机一端指向球，屏幕朝向自己。它更接近握球杆的习惯，也让手机长轴与杆身一致。

横握仍然可用。特征版本 2 对任意固定握法不变，但同一个人尽量保持同一种握法，力度映射会更稳定。手机上可以选择“我的握法”，每条录音都会记录握法。

### 13.6 方向改用“相对习惯的手腕转动”

0.16 的方向用起杆时的手机倾角（`atan2(gy, gz)`）。竖握时重力几乎沿手机长轴，这个量几乎不随左右变化，所以改为用姿态解算后的手腕转动角：

- **分解角速度**：一部分是绕挥杆平面法线的挥动，另一部分是绕杆身的转动；杆身方向在起杆时取平面内朝下的方向，并随挥动角转动。积分起杆到击球之间的杆身转动，就得到手腕转动角。
- **正负与左右**：从几何上推导，正的转动角表示杆面相对起杆时向右打开，与左右手无关。
- **映射到方向**：以这个人这类动作最近 30 杆的平均值为习惯零点；偏离 12° 以内视为不自主转动，方向为 0；超出部分每 45° 对应满偏，并乘以手机上的“方向灵敏度”。
- **手机提示**：每杆显示“手腕转动 −21°（习惯 −18°）”。

## 14. 取消握姿归零与引导校准；采集流程可暂停、可确认（0.18.0）

### 14.1 为什么可以去掉校准

原来的规则识别需要三样东西：主感应轴、满力角速度、方向零点。这三样都依赖握法，所以必须先“握姿归零 + 引导校准”。现在：

- **感应轴**：不再需要。候选峰值用 |ω|，判断用姿态解算后的挥杆坐标系，与握法无关。
- **满力值**：模型识别时由个人力度映射或总体映射给出；规则识别时取这个人这类动作最近 30 杆峰值的 90% 分位作满力参考，少于 5 杆用默认值（全挥杆 900、推杆 400 °/s）。
- **方向零点**：由手腕转动的习惯值替代（§13.6）。

因此手机启用体感后直接就绪，向服务器报告 `mode: model / auto`。电脑练习室的“握姿归零”“引导校准”按钮换成了“快速适应 · 2 分钟”。首次在某台手机上使用、还没有个人数据时，手机会提示做一次快速适应，它就是新的“校准”。

### 14.2 免校准规则（没有模型时的后备，也是模式识别的对照）

规则与模式识别共用同一套候选峰值，再用挥杆结构判断：

- 能找到上杆顶点（下挥前的低谷）；
- 上杆 ≥ 80 ms，下挥 40–700 ms；
- 上杆峰值在下挥峰值的 20%–120% 之间；
- 上杆前 300 ms 平均角速度 < 45 °/s，表示站稳了；
- 姿态解算后，上杆与下挥的旋转方向相反；
- 峰值 ≥ 120 °/s；峰值低于 300 °/s 的按推杆处理，下限 45 °/s。

在你的 90 条数据上对比：

| 方法 | 识别到挥杆 | 提前触发 | 非挥杆误触发 | 需要校准 |
|---|---|---|---|---|
| 旧版单轴规则 | 77%（推杆 9/20） | 4% | 50% | 是 |
| **免校准规则** | 89%（推杆 17/20） | 3% | 30% | 否 |
| 模式识别（5 折） | 91–97% | ≈0 | 5–15% | 否 |

训练报告里的“规则”列改为免校准规则的流式回放；旧版单轴规则的结果保存在 `metrics.legacyRule`。

### 14.3 采集流程

- **忽略小动作**：开始录制后，如果峰值没有达到该类动作的下限（全挥杆 150、切杆 100、推杆 35 °/s；非挥杆动作可由加速度变化触发），不记录也不报错，回到“保持静止”，并计入“忽略小动作”。
- **不像就先确认**：
  - 挥杆类：免校准规则判为挥杆，或模型判为挥杆类且置信度 ≥ 50%，才直接保存。
  - 非挥杆动作：如果规则和模型都认为是挥杆，也要先确认。
  - 不像的动作会显示原因（例如“没有明显的上杆，模型认为是非挥杆动作”），可以选“仍然保存”或“丢弃，重来”，手机和电脑上都能点；6 秒内不处理自动丢弃。
- **暂停 / 继续**：手机和电脑都能暂停。暂停时可以自由活动，什么都不记录；手机页面切到后台、或采集手机断线时自动暂停。
- **跳过这条**：例如提示的日常动作当时不方便做。
- **统计**：每组显示已保存、丢弃、跳过、忽略小动作的数量，结束后保留上一组的统计。
- **会话冲突**：另一台在线手机正在采集时不能开始新组；旧组属于同一台手机或手机已离线时，自动结束旧组。
- **电脑跟随**：手机发起采集或快速适应时，打开着的练习室会自动切到“数据采集”页。


## 15. 标签简化、5 档力度与小人的完整挥杆动作（0.20.0）

### 15.1 标签：挥杆 / 推杆 / 非挥杆

游戏里球杆已经由玩家或系统选定，模型不需要分辨“全挥杆还是切杆”，只需要回答两件事：**是不是一次击球、力度多大**。因此：

- 类别从 4 类减为 3 类：**挥杆**（原全挥杆 + 切杆 / 半挥杆）、**推杆**、**非挥杆动作**。推杆保留为单独一类：它的幅度、节奏和挥杆差别很大，与挥杆放在一起会让力度比较失去意义（满力推杆远比 20% 的挥杆“轻”）。
- 球杆弱标签相应简化：推杆 → 推杆，其他球杆 → 挥杆。

### 15.2 力度：5 档上杆幅度

“轻 / 中 / 重”三档全凭感觉，同一个人前后也难一致。0.20 改为按**上杆停在哪里**定档，人容易重复，而且直接对应小人的上杆高度：

| 档位 | 挥杆 | 推杆 |
|---|---|---|
| 20% | 手上杆到膝盖高 | 后摆约 10 厘米 |
| 40% | 手上杆到腰高 | 约 20 厘米 |
| 60% | 手上杆到胸口高 | 约 30 厘米 |
| 80% | 手上杆到肩高 | 约 45 厘米 |
| 100% | 完整上杆 | 约 60 厘米 |

- 每条样本保存力度值 `power`（0.2–1.0）与档位 `level`；采集默认“20%→100% 轮换”，每组都覆盖 5 档。建议量：挥杆每档 8 条、推杆每档 4 条、非挥杆 30 条。
- 力度头：成对排序损失只比较**可比较**的样本对（同一球手、同一类别；新档位之间相差 ≥ 0.1；与旧数据跨组时相差 ≥ 0.4）。幅度直连特征从 2 个增加到 3 个：|ω| 峰值、均方根，以及**上杆弧度**（沿挥杆主轴积分的最大回落）。
- 个人力度映射：每一档的分数中位数 → 档位力度，5 个锚点的分段线性单调映射（锚点不足两档时用分数分布的 2% / 97% 分位兜底）。
- 原型：挥杆与推杆按力度分成低（≤ 40%）/ 高两组原型，类别距离取最近的一组——20% 与 100% 的挥杆形态差别很大，一个原型代表不了。
- 新指标：**力度平均误差**与**误差 ≤ 10% 的比例**（用训练批次建立每人的映射，预测验证批次；没有个人映射时用总体映射）。

### 15.3 旧数据迁移

服务器第一次加载时自动迁移（原 `index.json` 另存为 `index.labels-v1.json`）：全挥杆 / 切杆 → 挥杆，推杆不变；轻中重按 0.19 真实录音里各档上杆弧度相对全力挥杆的比例换算成力度——全挥杆 轻 / 中 / 重 = 60% / 80% / 100%，切杆 = 30% / 40% / 50%，推杆 = 30% / 60% / 90%；原标签保存在 `legacy` 字段，旧数据只在同一旧类别内比较力度先后。

旧版 4 类模型仍可加载推理（“全挥杆 + 切杆”的概率合并为“挥杆”），服务器在有足够数据时自动用新标签重新完整训练一次并部署；旧模型不再做在线微调。

在你的 100 条真实数据上（迁移后自动重训，验证 18 条）：宏平均 F1 100%，流式回放准时识别 92.9%、非挥杆误触发 0%，力度排序相关 0.89、成对顺序 97%，力度平均误差 13.5%（旧数据只有三档且是估算值，按新 5 档采集后会更准）。

### 15.4 挥杆运动学：手机弧度

`shared/ml/kinematics.js` 把陀螺仪积分成**挥杆弧度**——绕挥杆平面法线转过的角度（上杆为正、送杆为负），不依赖模型：

1. 站定（角速度 < 28°/s、加速度 ≈ 1 g，持续 0.26 秒）时记下重力方向，把姿态清零；
2. 上杆时把每帧角速度转到站位参考系后累加，**累加向量的方向就是挥杆平面法线，长度就是上杆弧度**（不需要预先知道握法与平面）；
3. 弧度从最高点回落超过 max(8°, 15%) 才确认进入下挥（过滤上杆途中的抖动），冻结法线，继续沿法线积分到送杆；
4. 停稳后若手机回到站位的重力方向（< 16°），弧度归零；停在别处超过 3 秒视为离开击球准备。

同一个类 `LiveArc` 在手机上实时运行，离线分析（`recordingKinematics`）也逐帧调用它，保证校准数据与实时跟随一致。真实录音上的上杆弧度（中位数）：全挥杆 轻 / 中 / 重 127° / 141° / 173°，切杆 76° / 81° / 99°，推杆 32° / 45° / 47°——随力度单调增加，正好用来定义力度档位与小人姿势。

### 15.5 动作采样与小人姿势

小人的姿势用一个数 u 表示：0 站位，上杆 u = 力度档位 / 5（膝 0.2、腰 0.4、胸 0.6、肩 0.8、完整上杆 1），送杆为负（−1 收杆）。手机弧度 → u 的换算按每个人校准：

- **动作采样**（约 1 分钟）：慢慢上杆停在腰高、肩高、顶点各停 1 秒（以“非挥杆”入库，同时是很好的困难负样本），再完整挥杆并收杆停住（以“挥杆 100%”入库），各两次；
- 各档力度挥杆的上杆弧度中位数也作为校准点；
- 校准点不足时用默认参考（竖握：30° / 60° / 90° / 125° / 170° 对应 20%–100%），缺高档时按比例补齐。

小人有 13 个关键姿势（双手位置 + 杆身方向，上杆到腰高时杆身水平指向后方、顶点时越过头顶指向目标、收杆在目标一侧高处），双手走 Catmull-Rom 曲线，杆身方向归一化插值。

### 15.6 实时跟随与真实回放

- **实时跟随**：手机在动作中每 40 毫秒、站位时每 80 毫秒发送 u（带手机时间戳）；电脑把它们排成时间线，按“到达时刻 − 手机时间”的最小值换算时钟，延迟约 90 毫秒插值播放，25 Hz 的数据也能平滑。服务器转发间隔从 65 毫秒降到 30 毫秒。
- **击球**：手机随挥杆发送 25 Hz 的真实轨迹和击球峰值时刻。电脑把轨迹插入时间线，找到峰值后球杆第一次回到站位的时刻，让球在小人击球的那一刻起飞；之后继续跟随手机完成送杆与收杆。没有实时数据时，从上杆顶点开始按真实节奏回放；电脑输入的击球按力度决定固定动画的上杆高度。
- **慢放回放**：练习室“慢放上一杆”或按 R，按记录的真实轨迹以 0.35 倍速重放。
- 练习室的力量条在上杆时显示上杆高度，击球后显示模型给出的力量；新增“上杆幅度”读数（例如“80% · 到肩”）。
- 采集时如果已有个人校准，上杆幅度与提示档位相差两档以上会先请你确认，保证力度标签质量。
